# LIBS 三相机控制与采集软件

本软件面向华腾视觉（HuaTengVision）工业相机，在一台电脑上管理 1–3 台相机。三个角色均可单独使用，也可以任意组合：

- **触发相机 A / B**：工作在 SDK 硬件外触发模式，等待外部时序控制器输入信号；每次触发采集 1 帧，并自动保存到本次会话目录。
- **实时监控相机**：工作在连续采集模式，只做低延迟实时画面监控，不自动保存。
- **灵活连接**：任意角色都可选择“未分配”；只要至少分配 1 台相机即可连接和运行，不再要求三台全部在线。
- **可选保存**：关闭“保存外触发图片”后，触发相机仍按外部时序采集、显示末帧并累计接收数，但不创建目录、不保存图片或清单。
- 按相机唯一序列号绑定角色，避免 USB/GigE 枚举顺序变化后接错相机。
- 提供不连接硬件的三相机仿真模式，可完整测试连接、实时预览、双路触发、图片保存和清单记录。

界面沿用本项目位移平台软件的黑色工业仪器风格，包含设备角色、采集目录、触发控制、三路画面、曝光/增益/触发参数、统计与运行日志。

## 资料依据与实现方式

实现参考了同目录的《工业相机开发手册》、`SDK_API_CHS.chm`、`python_demo.zip`、厂商 `Demo.rar` 中的 `TriggerAndStrobe`、`TwoCameras`、`SaveImage` 示例，以及 `0-example/ThreeD-LIBS.rar` 的多设备应用结构。

关键 SDK 流程如下：

1. `CameraEnumerateDevice` 枚举设备，读取 `acSn` 建立固定角色映射。
2. 每台相机分别 `CameraInit`、查询能力、分配 ISP 缓冲区并 `CameraPlay`。
3. A/B 调用 `CameraSetTriggerMode(..., 2)`；监控相机调用 `CameraSetTriggerMode(..., 0)`。
4. A/B 可设置触发沿、触发延时和去抖时间；一次触发固定采集 1 帧。
5. 采集线程严格执行 `CameraGetImageBuffer` → `CameraImageProcess` → `CameraReleaseImageBuffer`。
6. 图像复制到独立内存后进入有界保存队列，由保存线程写盘，避免磁盘写入阻塞 SDK 取帧。

## 环境准备

1. Windows 10/11 x64。
2. Python 3.10 或更高版本，建议使用 **x64 Python**。
3. 安装摄像头资料目录中的 `HuaTengVision Camera Platform Setup(2.1.10.195_20260616).rar`。安装后 x64 SDK 通常位于 `C:\Windows\System32\MVCAMSDK_X64.dll`。
4. 安装 Python 依赖：

```powershell
python -m pip install -r requirements.txt
```

## 启动

双击 `start.bat`，或在本目录执行。启动脚本会优先使用系统 Python；如果当前电脑存在带 Pillow 的 Codex Python 运行时，也会自动复用：

```powershell
python main.py
```

首次启动默认为仿真模式。点击“刷新相机列表”，根据当前实际数量给需要的角色分配相机，其余角色选择“未分配”，再点击“连接所选相机”。

支持的典型组合包括：仅一台监控相机、仅一台触发相机、两台触发相机、一台触发加一台监控，以及三台相机全部连接。只有监控相机时“开始等待外触发”按钮会保持禁用，但实时监控和参数控制可正常使用。

## 实机采集步骤

1. 取消“仿真模式”，点击“刷新相机列表”。
2. 按序列号把在线相机分配给所需角色，不使用的角色选择“未分配”。软件关闭时会记住绑定关系。
3. 设置已连接相机的曝光和增益。监控相机可使用自动曝光；定量实验建议 A/B 使用固定曝光和增益。
4. 按实际接线选择 A/B 的上升沿或下降沿。高/低电平模式只在确有电平触发需求时使用。
5. 选择保存根目录，输入并列显示的文件夹名和文件名，再选择图片格式，点击“开始等待外触发”。文件夹名留空时自动按时间生成，文件名留空时使用 `image`。
6. 使用可用的“测试 A”“测试 B”或“测试触发 A + B”按钮验证已连接触发相机能够保存图像，然后接入外部时序控制器正式采集。
7. 完成后点击“停止采集并写盘”。软件会等待已进入队列的图像写完；实时监控仍继续运行。

如果本次只需要观察触发画面而不需要文件，请取消勾选“保存外触发图片”。保存目录、文件夹名、文件名和格式控件会自动禁用；点击开始后只采集和预览。软件默认使用加长窗口，左、中、右三个主面板上下对齐。

> 外触发端口电平、电压、极性和接线必须以具体相机型号的硬件说明为准。不要直接把未知电压信号接到相机 I/O。两台相机需要共同响应同一时序时，应使用合规的扇出/隔离方式，并确保信号地和触发脉冲宽度满足型号要求。

## 保存目录

每次启动采集都会创建一个新文件夹，已有目录绝不会覆盖。软件只为已连接的触发角色建立 `Camera A` 或 `Camera B` 目录：

```text
captures/
└─ capture_20260828_153000/
   ├─ session_info.txt
   ├─ Camera A/
   │  ├─ manifest.csv
   │  ├─ image-1.png
   │  └─ image-2.png
   └─ Camera B/
      ├─ manifest.csv
      ├─ image-1.png
      └─ image-2.png
```

`manifest.csv` 记录软件序号、本机时间、SDK 时间戳（0.1 ms）、分辨率、曝光、增益、触发帧标志、相机序列号和文件名，可用于后续实验数据对齐。A/B 使用各自清单，不强行假设两台相机到达电脑的顺序完全相同。

## 参数说明

- **曝光时间**：界面单位 ms，传给 SDK 时转换为 µs。
- **模拟增益**：界面安全输入范围 1–256；具体型号可能有更窄范围，SDK 会返回越界错误。
- **触发延时**：收到外触发信号后延迟指定微秒再曝光，仅部分型号支持。
- **去抖时间**：0–150000 µs；主要用于高/低电平或机械信号，去抖会引入额外延迟。
- **PNG**：无损，默认推荐；**JPG**：文件较小但有损；**BMP**：无压缩、占用空间大。
- 保存队列最大 256 帧。磁盘持续跟不上采集速度时，软件会明确累计“丢帧”并写入日志，不会无限占用内存。

## 高频触发与界面流畅度

- 触发相机收到的每一帧仍会进入独立保存队列；“末帧预览”只按约 6 FPS 刷新最新画面，不逐张播放已经过时的缩略图。
- 实时监控预览、统计数字和保存进度会自动合并刷新，避免高频触发消息阻塞界面主线程。
- PNG 保持无损，但采用低压缩等级降低 CPU 峰值；如触发频率极高且磁盘空间充足，BMP 写盘负担最低。
- 若界面“丢帧”计数持续增加，表示实际磁盘吞吐已经低于图像数据产生速度，应降低触发频率、改用更快磁盘或选择 BMP/JPG。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试覆盖 1/2/3 台相机连接、可选角色、角色唯一性、单路和双路触发保存、监控预览、PNG 有效性、清单内容和配置持久化。

## 生成独立 EXE（可选）

双击 `build_exe.bat`。生成文件位于 `dist/LIBS-Camera-Control/`。目标电脑仍需安装华腾视觉相机驱动和 SDK；Python SDK 绑定已随程序打包。
